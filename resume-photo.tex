[\textnormal{ LangGraph $\cdot$ MCP $\cdot$ SKILL $\cdot$ FastAPI $\cdot$ Redis}]
[2026.02—2026.05]
\vspace{0.3em}
\noindent \textbf{项目背景}: 面向 OnCall/SRE 场景的多智能体运维诊断平台，采用 Skill-first 架构，通过 Skill Router 自动匹配故障类型并加载诊断策略，结合 RAG 与 MCP 工具采集，完成从告警接入到结构化诊断报告输出的全链路智能诊断。
\begin{itemize}
  \item 针对全量 SOP 与工具列表注入 Planner 导致 prompt 过长、工具误选的问题，采用 Skill-first 多智能体架构，由 Skill Router 语义匹配故障类型后加载对应 Playbook 及工具白名单进行上下文收敛，使 Planner prompt tokens 下降 93.5\%，全链路 total tokens 下降 66.5\%。
  \item 针对运维知识库检索准确率不足的问题，采用 DashScope Embedding + Milvus 构建 RAG 知识库，通过 Query Rewrite 与 Hybrid Search 调优检索策略，将 R@1 从 83.3\% 提升至 91.7\%，MRR 从 0.882 提升至 0.938。
  \item 针对多工具串行执行导致诊断延迟高的问题，采用只读工具并行调度策略对互不依赖的 MCP 工具并发执行，使工具执行耗时从 1.06s 降至 0.22s，加速 4.88x。
  \item 针对 Plan-Execute-Replan 循环中重复步骤与 Skill 反复切换的问题，设计 AgentHarness 控制面，集中管理 Replanner 前置保护（最大步数 / 重复检测 / 快进）及 Reroute 配额机制，提升诊断链路稳定性与可控性。
  \item 针对诊断过程不透明的问题，采用 SSE 流式通信架构，前端实时展示 Skill 选择、工具调用过程、token 用量及 Markdown 诊断报告，并支持 token/时间预算的 warning 告警，提升诊断过程可观测性。
\end{itemize}
